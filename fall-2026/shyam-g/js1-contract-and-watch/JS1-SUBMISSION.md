## Job-Search Agent 1 — contract and watch

Watches one public Greenhouse board (`formlabs`, host `boards-api.greenhouse.io`), reports only
postings new since the last run, and judges each one twice: by the written rule in
[CONTRACT.md](CONTRACT.md) (a **record**, recomputable by hand) and by Claude under a prompt
contract (a **judgment**, labeled as one and validated).

### Toolchain
- Python 3.12.5, standard library only for the agent
- pytest 9.2.0 (`requirements.txt`)
- Claude Code CLI (`claude -p`) for the Claude judge. Each call is a fresh, tool-less
  conversation. No API key lives in this repo.
- Windows 11 / PowerShell. On macOS or Linux, use `.venv/bin/python` in place of `.venv\Scripts\python.exe`.

### Commands (from a fresh clone)
```powershell

.venv\Scripts\python.exe -m pytest tests -q            # offline, 30 tests

.venv\Scripts\python.exe agent.py run --board formlabs --label live
## seeded second run against a saved response:
.venv\Scripts\python.exe agent.py run --board formlabs --from-file <saved.json> --label seeded
```

## CONTRACT: Job-Search Agent 1

Written: 10/30/2026, before any implementation code existed.
Author: Shyam Sundar Jayaraman Gopalakrishnan.
Disclosure: the first draft of this contract was written by Claude; I
rewrote it on 10/30/2026. Amended 10/31/2026; see section 8. What I changed is listed in SOURCES.md.

### 1. In
- **Board:** one public job board, named by host and board token.
  - Host: `boards-api.greenhouse.io`
  - Board token: `formlabs` (verified 10/31/2026: returned JSON, 238 postings)
  - Endpoint: `https://boards-api.greenhouse.io/v1/boards/formlabs/jobs?content=true`
- **Résumé:** `persona/jordan_rivera.json`, a FICTIONAL persona (not me),
  with fields `name`, `email` (@example.com), `phone` (555 number),
  `target_titles[]`, `skills[]`, `locations[]`, `exclude_keywords[]`.
- **Needs:**
  - network access to hosts listed in `allowlist.txt` only
  - a writable `state/` folder holding `seen_ids.json` and `raw/` responses
  - a logged-in Claude Code CLI (`claude -p`) for the Claude judge;
    no API key or credential in the repo

### 2. Out
For each NEW posting only (never one already seen), one record:
- `posting_id`
- `rule_verdict`: `relevant` | `not_relevant`. A RECORD, computed by
  the rule in section 4. Anyone can recompute it.
- `claude_verdict`: `relevant` | `not_relevant`. A JUDGMENT, always
  labeled "Claude's judgment", never shown as fact.
- `justification`: names at least one résumé field and one posting
  field behind the verdict, for example
  `resume.skills: "sql", "power bi" matched posting.content`.
- Baseline run: reports zero new postings, saves the raw response and
  the ids it saw.

### 3. Refuses
- Fetching any host not in `allowlist.txt`.
- Showing a real résumé on screen, in logs, or on GitHub.
- Presenting a model's judgment as a fact.
- Applying, emailing or messaging anyone, or logging in anywhere.
- Accepting a Claude output that fails the validator. It is rejected
  and logged, never silently repaired.
- Judging a posting it has already seen.

### 4. The rule (rule_verdict)
Matching: case-insensitive, WHOLE-WORD/PHRASE. A term matches only if
the characters before and after it are not letters or digits (regex
`(?<!\w)term(?!\w)`, term escaped). So "sql" does not match "sqlite",
"excel" does not match "excellent". Input is the posting's plain text;
HTML in `content` is STRIPPED first: entities are unescaped, tags are
removed, then entities are unescaped again (Greenhouse escapes its HTML).
Pinned by `tests/test_extra.py::test_html_is_stripped_before_matching`.

A posting is `relevant` only if ALL hold:
1. TITLE: `title` matches at least one `resume.target_titles` entry.
2. LOCATION: `location.name` matches an entry in `resume.locations`,
   or matches "remote".
3. SKILLS: `content` matches at least 2 DISTINCT `resume.skills` entries.
4. EXCLUSIONS: neither `title` nor `content` matches any
   `resume.exclude_keywords` entry.
Otherwise `not_relevant`.

Decision: "ma" is NOT a location term (it matched "Germany" as a
substring). Consequence: "Worcester, MA" is `not_relevant` unless
"massachusetts" appears. I accept this limitation; fixture 1009 pins it.

Persona values live in `persona/jordan_rivera.json`. A TA with that
file and a posting can compute the verdict by hand in under a minute.

### 5. Wrong versions the tests must catch
1. **Verdicts paired with the wrong postings.** The verdicts are
   right but attached to the wrong ids (misalignment, sorting).
   Test: `test_each_id_gets_its_own_verdict` over 10 fixture postings.
2. **Justification that cites nothing real.** Text like "good fit for
   your background", or a cited résumé/posting field that does not
   exist. Test: `test_validator` rejects both.
(Optional third: baseline run reports existing postings as new.
Test: `test_baseline_reports_none_new`.)

### 6. What a failure looks like

On October 30, 2026, I expect the most likely failure to be that the
rule rejects real fits such as "Supply Planner" or "Business Operations
Analyst" because my target_titles list only contains exact phrases,
which I would notice because my hand label says relevant while
rule_verdict says not_relevant for those postings in the output file.

### 7. Claude output format (validated)
JSON only, no prose, no code fences:
{"posting_id": "<string>",
 "verdict": "relevant" | "not_relevant",
 "resume_fields": ["skills", "locations", ...],
 "posting_fields": ["title", "content", "location"],
 "justification": "<one to three sentences>"}
Validator rejects: invalid JSON, extra keys, a verdict outside the two
values, empty field lists, field names not in the résumé or posting
schema, or a `posting_id` that does not match the posting asked about.

### 8. Amendments (10/31/2026, after implementation existed)
Made at my direction after `agent.py` was written; the rule in section 4
did not change except where it was left undecided.
1. Board token filled in: `formlabs` (Somerville, MA, matches persona
   `locations`).
2. HTML decision made: stripped before matching (was "DECIDE").
3. Claude access: the Claude Code CLI replaces "an Anthropic API key in
   an environment variable". Each call is a fresh, tool-less conversation.
4. Résumé validation added: `agent.validate_resume` refuses a résumé
   missing a rule field, or whose email is not @example.com or phone is
   not a 555 number, before any fetch (`tests/test_resume.py`).

## Sampling report (Chapter 1)

**Status: Claude runs collected 2026-10-31 22:48–23:07. Hand labels added 23:49 and scored 23:50
(`python study.py score sampling.json`).**

### Setup
- 5 postings from the live Formlabs response, picked before any labels or Claude results existed to

- Raw outputs, including every reply: `results/sampling.json`. All 20 outputs passed the validator.

### Results
| posting_id | title | Claude verdicts (4 fresh runs) | rule (record) | Claude = rule | my hand label |
|---|---|---|---|---|---|
| 8311099 | Strategy & Operations Analyst | relevant ×4 | relevant | 4/4 | relevant (Claude 4/4) |
| 8161780 | Global Sourcing Intern (Winter/Spring 2027) | not_relevant ×3, **relevant ×1** | not_relevant | 3/4 | not_relevant (Claude 3/4) |
| 8335610 | Mechanical Project Manager | not_relevant ×4 | not_relevant | 4/4 | **relevant** (Claude 0/4) |
| 8281689 | Product Manager, Software | not_relevant ×4 | not_relevant | 4/4 | **relevant** (Claude 0/4) |
| 7684675 | Manufacturing Ops Leader | not_relevant ×4 | not_relevant | 4/4 | **relevant** (Claude 0/4) |

### What this can and cannot show
- **Can:** the same prompt on the same posting doesn't always return the same verdict. 8161780 flipped
  once in 4 runs. A single Claude call on that posting is not a stable answer, which is why the agent
  keeps the rule as the record and labels Claude's answer as a judgment.
- **Can:** 4 of the 5 postings repeated 4/4. Repeating proves **repeatability, not correctness**.
- **Against my hand labels:** Claude matched 7 of 20 verdicts, and the rule matched 2 of 5 postings. The three
  postings where Claude was **4/4 consistent and 0/4 correct** (8335610, 8281689, 7684675) are the
  clearest case of repeatability without correctness: Claude repeated the contract rule's answer
  every time, and my labels disagree with that rule.
- **Unresolved:** 7684675 is in Perrysburg, OH, and my written labeling rule says Boston or remote,
  so my own label contradicts my rule. The labels were made in a hurry at 23:49 and were not re-checked. Agreement with the rule (19/20) is not correctness either, because the prompt restates the
  rule, so agreement is partly built in.
- **Cannot:** anything about the size of the variation in general. With 4 samples, one flip is
  consistent with a true flip rate anywhere from a few percent to over half.
- The posting that flipped is the borderline one: "sourcing" is close to `procurement`, but it's an
  internship. Variation showing up where the rule is least clear is what you'd expect. On five postings
  that is an observation, not a finding.

| | dev (10) | held-out (10) |
|---|---|---|
| baseline | **6/10** | **7/10** |
| revision | **5/10** | **7/10** |

Every miss is the same kind: I labeled a posting `relevant` and both Claude and the contract rule said
`not_relevant`. The dev misses are 7684675, 8327414, 8241540 and 8167038; the held-out misses are
8281689, 8335610 and 8333766. Claude never disagreed with the rule. The baseline prompt restates the
rule, so it inherits the rule's misses. **The revision did not help:** dev went from 6/10 to 5/10, and held-out stayed at 7/10. On dev, Claude still
rejected the same 4 postings, and it flipped 8161780 (Global Sourcing Intern) to `relevant`, a
posting I had labeled `not_relevant` with the note "internship, but sourcing = procurement". So
the one changed verdict moved the wrong way. One posting is within the noise seen in `SAMPLING.md`
(that same posting flipped 1 of 4 times under the baseline), so I can't say the revision is worse.
I can only say it is not shown to be better. Several of my labels (an engineering technician, a materials scientist, a
support role in Milwaukee, an ops leader in Ohio) do not obviously follow my own written rule either,
and that is unresolved.

Also measured: **agreement of the baseline prompt with the rule**: dev 10/10, held-out
10/10 (`results/experiment-baseline-*.json`). This is not a pass rate. The prompt states the rule, so
high agreement mostly shows that Claude followed the stated rule and produced valid output, not that
either one is right. Only 1 of the 20 postings is rule-relevant (8311099), so this set barely tests the
`relevant` side at all.

Note on order: the held-out baseline was run at the same time as dev, before any labeling, and its
results were not used to choose anything. No revision exists, so nothing was tuned on held-out.

### How little ten cases show
A change from 7/10 to 8/10 is one posting. On a ten-case set that is within what re-sampling the same
prompt can produce on its own: in `SAMPLING.md` one posting flipped verdict in 1 of 4 identical runs. Even with labels, 10 dev and 10 held-out cases, of which only 1 is rule-relevant, could not separate two prompts unless they differed by several postings.

## 5. Action-surface comparison (Chapter 3)
_Source: `ACTION-SURFACE.md`_

## Action-surface comparison (Chapter 3)

Task: judge posting 8311099 (Formlabs, Strategy & Operations Analyst, Somerville, MA) against the
fictional persona under `prompts/baseline.txt`. Ways 1 and 2 were run on 2026-10-31; the output is in
`surface/runs.txt`. Both returned `relevant`, which matches the rule's record. Way 3 is written up from
its design and was **not** run as a free agent (see the last section).

| | 1. Paste into chat | 2. Give Claude a file to read | 3. Let an agent fetch and write its own state |
|---|---|---|---|
| How it ran | `claude -p --tools ""` with the posting in the prompt (`surface/1-paste-prompt.txt`) | `claude -p --tools Read --allowedTools Read`; the prompt names `surface/posting-8311099.json` | Claude with web fetch + file write tools, told to fetch the board, diff against `seen_ids.json`, and update it |
| Can read | only the prompt text I chose | the prompt, **plus any file the Read tool can open**, not just the one named | the network, the whole working tree, anything its tools reach |
| Can write | nothing | nothing | the state file, plus any other file its write tool can reach |
| Can send | nothing beyond its reply | nothing beyond its reply | HTTP requests to any host, unless a hook or permission rule blocks them |
| Authority needed | none: I chose every byte it sees | file-system read permission on my machine | network access + write access + trust that it does not touch other files |
| What could go wrong | I paste the wrong posting or a real résumé; the answer is unvalidated prose unless I run the validator | reads a file I did not intend (e.g. a real résumé on the same disk); the path is wrong and it judges something else | fetches a host outside the allow-list; rewrites or wipes `seen_ids.json`, so old postings come back as "new" or new ones are silently marked seen; nobody can recompute what happened; prompt injection in a posting body steers a tool call |

### Choice: the least autonomy that suffices

The **fetching and the state are plain code** (`agent.py`): an allow-listed `https` fetch, a raw
response saved as evidence, and a set difference on ids. None of that needs judgment, so none of it is
given to the model. **Claude gets surface 1 only**: one posting's text, the four rule-relevant résumé
fields (no name, email or phone; pinned by `test_prompt_never_contains_contact_details`), no tools,
and an output the validator either accepts or rejects.

Why not 2: reading a file adds no information the prompt doesn't already carry. It does add authority:
the Read tool is not scoped to the one file, and the real résumé lives on the same machine.

Why not 3: every part an agent would do with tools is deterministic and testable in code. Handing it
over trades a recomputable record for an unrecomputable one. It also puts the one thing the agent must
never get wrong, the seen-ids state, in the hands of the step whose output varies from run to run
(see `SAMPLING.md`).

### Not run
Way 3 was not executed as a free-running Claude agent. Giving it network and write access to show what
goes wrong is the risk the table describes. The comparison for Way 3 rests on its design, not on an
observed run.

## 15. Code: agent.py
_Source: `agent.py`_

```python
"""Job-Search Agent 1: watch one board, judge new postings two ways.

Implements CONTRACT.md. Python 3.12, standard library only (pytest for tests).

  python agent.py run --board <token>                      # live fetch (allow-listed host only)
  python agent.py run --board <token> --from-file f.json --label seeded
  python agent.py run --board <token> --claude             # also ask Claude (a judgment)
"""
import argparse
import datetime as dt
import html
import json
import pathlib
import re
import subprocess
import sys
import urllib.parse
import urllib.request

ROOT = pathlib.Path(__file__).parent
ALLOWLIST_FILE = ROOT / "allowlist.txt"
STATE = ROOT / "state"
OUT_DIR = ROOT / "output"
ENDPOINT = "https://boards-api.greenhouse.io/v1/boards/{board}/jobs?content=true"

# CONTRACT section 4 leaves this open: HTML in `content` is stripped before matching.
# Greenhouse returns entity-escaped HTML, so "&lt;li&gt;SQL" would otherwise be the text.
STRIP_HTML = True

VERDICTS = ("relevant", "not_relevant")
RESUME_FIELDS = ("target_titles", "skills", "locations", "exclude_keywords")
POSTING_FIELDS = ("title", "content", "location")
CLAUDE_KEYS = {"posting_id", "verdict", "resume_fields", "posting_fields", "justification"}
MIN_SKILLS = 2


# ---------- résumé validation (fictional persona only) ----------

def validate_resume(resume: dict) -> dict:
    """Reject a résumé the rule cannot use, or one that looks real (CONTRACT sections 1 and 3)."""
    if not isinstance(resume, dict):
        raise ValueError("résumé must be a JSON object")
    for key in RESUME_FIELDS:
        vals = resume.get(key)
        if not isinstance(vals, list) or not all(isinstance(v, str) and v.strip() for v in vals):
            raise ValueError(f"résumé.{key} must be a list of non-empty strings")
    for key in ("target_titles", "skills", "locations"):
        if not resume[key]:
            raise ValueError(f"résumé.{key} is empty; the rule can never match")
    if not str(resume.get("email", "")).lower().endswith("@example.com"):
        raise ValueError("refused: email is not @example.com, so this may be a real résumé")
    if "555" not in re.sub(r"\D", "", str(resume.get("phone", ""))):
        raise ValueError("refused: phone is not a 555 number, so this may be a real résumé")
    return resume


# ---------- fetching (allow-list enforced) ----------

def allowlist() -> set[str]:
    lines = ALLOWLIST_FILE.read_text(encoding="utf-8").splitlines()
    return {ln.strip().lower() for ln in lines if ln.strip() and not ln.startswith("#")}


def fetch(url: str) -> bytes:
    host = (urllib.parse.urlparse(url).hostname or "").lower()
    if urllib.parse.urlparse(url).scheme != "https" or host not in allowlist():
        raise PermissionError(f"refused: host {host!r} is not on the allow-list")
    req = urllib.request.Request(url, headers={"User-Agent": "js1-job-agent (course project)"})
    with urllib.request.urlopen(req, timeout=30) as r:
        return r.read()


# ---------- the rule (a record) ----------

def plain_text(s: str) -> str:
    if not STRIP_HTML:
        return s or ""
    s = html.unescape(s or "")
    s = re.sub(r"<[^>]+>", " ", s)
    return html.unescape(s)


def matched(terms, text: str) -> list[str]:
    """Terms that appear as whole words/phrases, case-insensitive (CONTRACT section 4)."""
    text = text.lower()
    return [t for t in terms if re.search(r"(?<!\w)" + re.escape(t.lower()) + r"(?!\w)", text)]


def rule_checks(resume: dict, posting: dict) -> dict:
    title = posting.get("title") or ""
    location = (posting.get("location") or {}).get("name") or ""
    content = plain_text(posting.get("content") or "")
    return {
        "title": matched(resume["target_titles"], title),
        "location": matched(list(resume["locations"]) + ["remote"], location),
        "skills": sorted(set(matched(resume["skills"], content))),
        "exclusions": sorted(set(matched(resume["exclude_keywords"], title + "\n" + content))),
    }


def judge_rule(resume: dict, posting: dict) -> str:
    c = rule_checks(resume, posting)
    ok = c["title"] and c["location"] and len(c["skills"]) >= MIN_SKILLS and not c["exclusions"]
    return "relevant" if ok else "not_relevant"


def rule_justification(resume: dict, posting: dict) -> str:
    c = rule_checks(resume, posting)
    parts = [
        f"resume.target_titles vs posting.title: {c['title'] or 'no match'}",
        f"resume.locations(+remote) vs posting.location.name: {c['location'] or 'no match'}",
        f"resume.skills vs posting.content: {c['skills'] or 'none'} "
        f"({len(c['skills'])}/{MIN_SKILLS} needed)",
        f"resume.exclude_keywords vs posting.title+content: {c['exclusions'] or 'none'}",
    ]
    return "; ".join(parts)


# ---------- the watch ----------

def new_postings(seen_ids: set, response: dict, baseline: bool = False) -> list:
    if baseline:
        return []
    return [j for j in response.get("jobs", []) if str(j["id"]) not in seen_ids]


def load_seen(state: pathlib.Path = STATE) -> set[str] | None:
    f = state / "seen_ids.json"
    if not f.exists():
        return None
    return set(json.loads(f.read_text(encoding="utf-8"))["seen_ids"])


def save_seen(seen: set[str], board: str, run_at: str, state: pathlib.Path = STATE) -> None:
    state.mkdir(exist_ok=True)
    (state / "seen_ids.json").write_text(json.dumps(
        {"board": board, "updated": run_at, "seen_ids": sorted(seen)}, indent=2), encoding="utf-8")


# ---------- Claude (a judgment) ----------

PROMPT_FILE = ROOT / "prompts" / "baseline.txt"


def build_prompt(resume: dict, posting: dict, template_path: pathlib.Path = PROMPT_FILE) -> str:
    # Only the fields the rule uses go to Claude: no name, email or phone.
    profile = {k: resume[k] for k in RESUME_FIELDS}
    post = {
        "posting_id": str(posting["id"]),
        "title": posting.get("title"),
        "location": (posting.get("location") or {}).get("name"),
        "content": plain_text(posting.get("content") or "")[:6000],
    }
    return (template_path.read_text(encoding="utf-8")
            .replace("{{RESUME}}", json.dumps(profile, indent=2))
            .replace("{{POSTING}}", json.dumps(post, indent=2)))


def validate_claude(raw: str, posting_id: str, resume: dict) -> dict:
    try:
        out = json.loads(raw)
    except (json.JSONDecodeError, TypeError) as e:
        raise ValueError(f"not JSON: {e}")
    if not isinstance(out, dict) or set(out) != CLAUDE_KEYS:
        raise ValueError(f"keys must be exactly {sorted(CLAUDE_KEYS)}")
    if out["posting_id"] != str(posting_id):
        raise ValueError(f"posting_id {out['posting_id']!r} != {posting_id!r}")
    if out["verdict"] not in VERDICTS:
        raise ValueError(f"verdict {out['verdict']!r} not in {VERDICTS}")
    for key, allowed in (("resume_fields", set(RESUME_FIELDS) & set(resume)),
                         ("posting_fields", set(POSTING_FIELDS))):
        vals = out[key]
        if not isinstance(vals, list) or not vals:
            raise ValueError(f"{key} must be a non-empty list")
        bad = [v for v in vals if v not in allowed]
        if bad:
            raise ValueError(f"{key} names fields that do not exist: {bad}")
    if not isinstance(out["justification"], str) or not out["justification"].strip():
        raise ValueError("justification is empty")
    return out


def ask_claude(prompt: str, model: str | None = None) -> str:
    """One fresh, tool-less conversation via the Claude Code CLI (`claude -p`)."""
    cmd = ["claude", "-p", "--output-format", "text", "--tools", ""]
    if model:
        cmd += ["--model", model]
    r = subprocess.run(cmd, input=prompt, capture_output=True, text=True, encoding="utf-8",
                       shell=sys.platform == "win32", timeout=300)
    if r.returncode != 0:
        raise RuntimeError(f"claude exited {r.returncode}: {r.stderr.strip()[:300]}")
    return r.stdout.strip()


def claude_verdict(resume: dict, posting: dict, model: str | None = None) -> dict:
    raw = ask_claude(build_prompt(resume, posting), model)
    try:
        v = validate_claude(raw, str(posting["id"]), resume)
        return {"label": "Claude's judgment (not a fact)", "valid": True, **v}
    except ValueError as e:
        return {"label": "Claude's judgment (not a fact)", "valid": False,
                "rejected_because": str(e), "raw": raw}


# ---------- run ----------

def run(board: str, from_file: str | None, label: str, use_claude: bool, resume_path: str,
        model: str | None = None, state: pathlib.Path = STATE) -> dict:
    run_at = dt.datetime.now().astimezone().isoformat(timespec="seconds")
    stamp = run_at[:19].replace(":", "")
    resume = validate_resume(json.loads(pathlib.Path(resume_path).read_text(encoding="utf-8")))

    if from_file:
        body = pathlib.Path(from_file).read_bytes()
        source = f"{label}: saved file {pathlib.Path(from_file).as_posix()}"
    else:
        url = ENDPOINT.format(board=urllib.parse.quote(board))
        body = fetch(url)
        source = f"live: {url}"
    (state / "raw").mkdir(parents=True, exist_ok=True)
    raw_path = state / "raw" / f"{stamp}-{board}-{label}.json"
    raw_path.write_bytes(body)
    response = json.loads(body)

    seen = load_seen(state)
    baseline = seen is None
    new = new_postings(seen or set(), response, baseline=baseline)
    results = []
    for p in new:
        rec = {
            "posting_id": str(p["id"]),
            "title": p.get("title"),
            "location": (p.get("location") or {}).get("name"),
            "url": p.get("absolute_url"),
            "rule_verdict": judge_rule(resume, p),
            "rule_label": "record (recomputable from CONTRACT section 4)",
            "justification": rule_justification(resume, p),
        }
        if use_claude:
            rec["claude"] = claude_verdict(resume, p, model)
        results.append(rec)

    all_ids = {str(j["id"]) for j in response.get("jobs", [])}
    report = {"run_at": run_at, "board": board, "source": source,
              "raw_saved": raw_path.relative_to(ROOT).as_posix(), "baseline": baseline,
              "postings_in_response": len(all_ids), "new": len(results), "results": results}
    OUT_DIR.mkdir(exist_ok=True)
    (OUT_DIR / f"run-{stamp}-{label}.json").write_text(json.dumps(report, indent=2), encoding="utf-8")
    # Ids are marked seen only after the report is on disk, so a crash cannot swallow new postings.
    save_seen((seen or set()) | all_ids, board, run_at, state)
    return report


def main(argv=None):
    ap = argparse.ArgumentParser(description=__doc__, formatter_class=argparse.RawTextHelpFormatter)
    sub = ap.add_subparsers(dest="cmd", required=True)
    r = sub.add_parser("run")
    r.add_argument("--board", required=True, help="Greenhouse board token")
    r.add_argument("--from-file", help="use a saved response instead of fetching")
    r.add_argument("--label", default="live", help="tag for this run, e.g. live or seeded")
    r.add_argument("--resume", default=str(ROOT / "persona" / "jordan_rivera.json"))
    r.add_argument("--claude", action="store_true", help="also get Claude's judgment")
    r.add_argument("--model", help="Claude model alias passed to `claude -p`")
```

## 16. Code: study.py
_Source: `study.py`_

```python
"""Step 4 tooling: pick postings to label, sample Claude, run the prompt experiment.

  python study.py pick --raw state/raw/<file>.json          # writes labels/hand_labels.csv (hand_label blank)
  python study.py sample --n 4 --ids 1,2,3,4,5               # 5 postings x 4 fresh conversations
  python study.py experiment --prompt prompts/baseline.txt --split dev
"""
import argparse
import csv
import json
import pathlib
import random
from collections import Counter

import agent

ROOT = agent.ROOT
LABELS = ROOT / "labels" / "hand_labels.csv"
RESULTS = ROOT / "results"
RESUME = agent.validate_resume(json.loads((ROOT / "persona" / "jordan_rivera.json").read_text(encoding="utf-8")))


def postings_from(raw_path: str) -> dict[str, dict]:
    jobs = json.loads(pathlib.Path(raw_path).read_text(encoding="utf-8"))["jobs"]
    return {str(j["id"]): j for j in jobs}


def read_labels() -> list[dict]:
    with LABELS.open(encoding="utf-8-sig", newline="") as f:
        rows = list(csv.DictReader(f))
    for r in rows:  # spreadsheet edits can leave stray spaces around a label
        r["hand_label"] = (r.get("hand_label") or "").strip()
    return rows


def pick(raw_path: str, seed: int = 7375) -> None:
    """20 postings: every target-title hit (up to 10) plus random others; then a seeded dev/held-out split."""
    jobs = postings_from(raw_path)
    hits = [i for i, j in jobs.items() if agent.matched(RESUME["target_titles"], j["title"])]
    rng = random.Random(seed)
    hits = rng.sample(sorted(hits), min(10, len(hits)))
    others = rng.sample(sorted(set(jobs) - set(hits)), 20 - len(hits))
    chosen = hits + others
    rng.shuffle(chosen)
    LABELS.parent.mkdir(exist_ok=True)
    with LABELS.open("w", encoding="utf-8", newline="") as f:
        w = csv.writer(f)
        w.writerow(["posting_id", "split", "title", "location", "url", "hand_label", "hand_note"])
        for n, i in enumerate(chosen):
            j = jobs[i]
            w.writerow([i, "dev" if n < 10 else "heldout", j["title"],
                        (j.get("location") or {}).get("name"), j.get("absolute_url"), "", ""])
    print(f"wrote {LABELS.relative_to(ROOT)}: {len(chosen)} postings ({len(hits)} title hits). "
          "Fill hand_label (relevant/not_relevant) BEFORE running sample or experiment.")


def judge_many(jobs, ids, prompt_path, n, out_name):
    labels = {r["posting_id"]: r["hand_label"] for r in read_labels()}
    rows = []
    for i in ids:
        p = jobs[i]
        for k in range(n):
            raw = agent.ask_claude(agent.build_prompt(RESUME, p, pathlib.Path(prompt_path)))
            try:
                v = agent.validate_claude(raw, i, RESUME)["verdict"]
            except ValueError as e:
                v = f"INVALID: {e}"
            rows.append({"posting_id": i, "try": k + 1, "claude_verdict": v,
                         "rule_verdict": agent.judge_rule(RESUME, p), "hand_label": labels.get(i, ""),
                         "raw": raw})
            print(i, k + 1, "valid" if not v.startswith("INVALID") else "INVALID", flush=True)
    RESULTS.mkdir(exist_ok=True)
    (RESULTS / out_name).write_text(json.dumps(rows, indent=2), encoding="utf-8")
    return rows


def summarize(rows):
    by = {}
    for r in rows:
        by.setdefault(r["posting_id"], []).append(r)
    print("\nposting_id | claude verdicts | agree w/ hand | rule | hand")
    for i, rs in by.items():
        c = Counter(r["claude_verdict"] for r in rs)
        hand = rs[0]["hand_label"]
        agree = sum(r["claude_verdict"] == hand for r in rs)
        print(f"{i} | {dict(c)} | {agree}/{len(rs)} | {rs[0]['rule_verdict']} | {hand or 'UNLABELED'}")
    labeled = [r for r in rows if r["hand_label"]]
    if labeled:
        ok = sum(r["claude_verdict"] == r["hand_label"] for r in labeled)
        print(f"\nClaude pass rate vs hand labels: {ok}/{len(labeled)}")
        rule_ok = len({r['posting_id'] for r in labeled if r["rule_verdict"] == r["hand_label"]})
        print(f"Rule pass rate vs hand labels: {rule_ok}/{len({r['posting_id'] for r in labeled})}")


def main():
    ap = argparse.ArgumentParser()
    sub = ap.add_subparsers(dest="cmd", required=True)
    a = sub.add_parser("pick"); a.add_argument("--raw", required=True)
    s = sub.add_parser("sample"); s.add_argument("--raw", required=True)
    s.add_argument("--ids", required=True); s.add_argument("--n", type=int, default=4)
    s.add_argument("--prompt", default=str(agent.PROMPT_FILE))
    e = sub.add_parser("experiment"); e.add_argument("--raw", required=True)
    e.add_argument("--prompt", required=True); e.add_argument("--split", choices=["dev", "heldout"], required=True)
    c = sub.add_parser("score"); c.add_argument("file", help="results/<file>.json; joins hand labels and prints pass rates")
    args = ap.parse_args()
    if args.cmd == "pick":
        return pick(args.raw)
    if args.cmd == "score":
        rows = json.loads((RESULTS / args.file).read_text(encoding="utf-8"))
        labels = {r["posting_id"]: r["hand_label"] for r in read_labels()}
        if any(not labels.get(r["posting_id"]) for r in rows):
            raise SystemExit("refused: some postings in this file have no hand label yet.")
        for r in rows:
            r["hand_label"] = labels[r["posting_id"]]
        (RESULTS / args.file).write_text(json.dumps(rows, indent=2), encoding="utf-8")
        return summarize(rows)
    jobs = postings_from(args.raw)
    # Claude's verdicts are saved but never printed here, so they cannot steer hand labeling.
    if args.cmd == "sample":
        judge_many(jobs, args.ids.split(","), args.prompt, args.n, "sampling.json")
    else:
        ids = [r["posting_id"] for r in read_labels() if r["split"] == args.split]
        name = f"experiment-{pathlib.Path(args.prompt).stem}-{args.split}.json"
        rows = judge_many(jobs, ids, args.prompt, 1, name)
    print(f"saved results/. Score after labeling: python study.py score <file>")


if __name__ == "__main__":
    main()
```
